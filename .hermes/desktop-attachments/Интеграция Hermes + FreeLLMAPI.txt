Техническое задание
Интеграция Hermes + FreeLLMAPI (Pandora AI Gateway)
Статус

Draft

Цель

Интегрировать Hermes с локальным экземпляром FreeLLMAPI таким образом, чтобы для повседневной работы пользователь запускал только Hermes.

FreeLLMAPI должен стать внутренним компонентом Hermes, а не отдельной программой, требующей ручного запуска.

Исходные данные

Проект установлен в:

D:\AI\pandora-ai-gateway

Основа:

https://github.com/tashfeenahmed/freellmapi

FreeLLMAPI успешно запускается.

Используется как локальный OpenAI-compatible API Gateway.

Основные требования
1. Автоматический запуск

При запуске Hermes необходимо:

Проверить, работает ли FreeLLMAPI.
Если не работает — автоматически запустить его.
Дождаться полной готовности сервиса.
Только после этого запускать основной процесс Hermes.

Пользователь не должен выполнять никаких дополнительных действий.

2. Проверка готовности

Перед использованием API Hermes должен убедиться, что Gateway действительно готов.

Например, через

http://127.0.0.1:3001/health

или другой штатный механизм проверки.

3. Если Gateway уже запущен

Hermes не должен запускать второй экземпляр.

Необходимо использовать уже работающий процесс.

4. Никаких лишних окон

Запуск Gateway должен происходить без появления дополнительных окон:

PowerShell
CMD
npm

не должны оставаться открытыми пользователю.

5. Минимум ручных действий

После первоначальной установки пользователь не должен:

открывать терминал;
переходить в папку проекта;
запускать npm run dev;
помнить какие-либо команды.

Рабочий сценарий должен состоять из одного действия:

Запустить Hermes
Администрирование

Несмотря на автоматический запуск, необходимо сохранить возможность отдельного управления FreeLLMAPI.

Для этого требуется отдельный режим.

Например:

Pandora AI Gateway Manager

или аналогичный механизм.

Его задача:

при необходимости запускать Gateway;
автоматически открывать Web UI;
позволять управлять:
API Keys;
Providers;
Models;
Routing;
настройками.

Пользователь не должен запускать Web UI вручную через npm.

Работа с FreeModel

Планируется использовать несколько API-ключей FreeModel.

На текущий момент:

6 API Keys

Каждый ключ имеет собственный бесплатный лимит.

Необходимо исследовать:

Поддерживает ли FreeLLMAPI несколько ключей одного OpenAI-compatible Provider.
Поддерживает ли автоматическое переключение между ними.
Если не поддерживает —

предложить минимальную доработку проекта.

Поведение при ошибках

Необходимо исследовать обработку:

401 Unauthorized
429 Too Many Requests
лимитов FreeModel
временной недоступности моделей

Если возможен автоматический переход на следующий ключ —

реализовать его.

Предпочтительный порядок использования ключей

Если несколько ключей доступны одновременно:

предпочтительно использовать стратегию:

Key 1
↓

Key 2
↓

Key 3
↓

...
↓

Key 6

либо Round Robin (циклическое распределение запросов), если это лучше соответствует архитектуре FreeLLMAPI.

Архитектура

Предпочтительно максимально использовать существующие возможности FreeLLMAPI.

Не делать форк проекта без необходимости.

Если изменения неизбежны —

они должны быть минимальными и хорошо документированными.

Документация

По завершении необходимо предоставить:

описание архитектуры;
список внесённых изменений;
какие файлы были изменены;
как работает запуск;
как работает остановка;
как добавлять новые ключи;
как обновлять FreeLLMAPI;
как восстановить систему после обновления.

Критерий успешного выполнения

После завершения настройки пользователь не должен помнить никаких команд npm, путей к проекту или последовательности запуска. Работа с системой должна сводиться к двум действиям:

Работа — запуск Hermes.
Настройка — запуск Pandora AI Gateway Manager.

Все остальные процессы должны выполняться автоматически.
